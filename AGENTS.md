# MindSpeed-LLM agent guidance

## Scope and runtime

- This is an Ascend/NPU distributed LLM training project. The repository is normally executed on an Ascend server, not on a personal CPU-only machine; do not claim that training or NPU profiling was locally verified here.
- Run commands from the repository root. Python requires >=3.10; `requirements.txt` does not provide PyTorch, TorchNPU, CANN, Megatron, MindSpeed, or FSDPTurbo.
- Before NPU work, source the server-specific CANN and ATB environments (CI commonly uses `/usr/local/Ascend/ascend-toolkit/set_env.sh` and `/usr/local/Ascend/nnal/atb/set_env.sh`).
- MCore launchers must import `from mindspeed_llm import megatron_adaptor` before importing Megatron. `mindspeed_llm` import behavior depends on `TRAINING_BACKEND`; `MINDSPEED_LLM_VERSION=018` redirects the package to `tests/mindspeed_llm/`.
- External runtime packages are supplied by `3rdparty/` or CI (Megatron `core_v0.12.1`, MindSpeed, and optionally FSDPTurbo); initializing submodules alone does not necessarily make their Python packages importable.
- FSDP2 entrypoint is `train_fsdp2.py` and code is under `mindspeed_llm/fsdp2/`; source the relevant `examples/fsdp2/env_config.sh` before launching. YAML configuration is followed by dotted CLI overrides, with CLI values taking precedence.

## Trace analysis and DAG work

- The working goal is to reconstruct NPU computation and communication from `view_trace.json` and develop a **C++ multi-rank compute/communication DAG generator**. Real traces are unavailable for confidentiality reasons; do not request them or treat synthetic results as real-trace validation.
- Profiling is configured with `--profile`, `--profile-step-start`, `--profile-step-end` (end-exclusive), `--profile-ranks`, `--profile-level`, `--profile-with-cpu`, and `--profile-save-path`; the training profiler writes trace output through `torch_npu.profiler.tensorboard_trace_handler`.
- Do not expect real `view_trace.json`/`trace_view.json` files in this workstation context: they are generated after server-side training and may be confidential. Use the checked-in sample fixture or synthetic traces for offline work, and avoid printing full traces because they can be hundreds of MB.
- `mindspeed_llm/tools/chakra_trace.py` is the standard Python-library-only offline parser: it validates top-level `traceEvents`, normalizes events, infers only trace-supported dependencies, and can export Chakra protobuf. Run it from the root, e.g. `python mindspeed_llm/tools/chakra_trace.py --input path/to/trace_view.json`.
- The root `export_dag.cpp` is a separate C++ DAG exporter for `view_trace.json`/`trace_view.json`; it classifies compute, collective, and P2P events, adds same-stream and matched cross-stream edges, and writes text DAG output. Build with `g++ -O2 -Wall -Wextra export_dag.cpp -o export_dag`; run `./export_dag <trace> <dag_output>` (both arguments have defaults).
- `export_dag.cpp` is currently a single-trace/single-card baseline, not a completed multi-rank implementation: stream buckets use only `stream_id`, and synchronization starts use only `sync_id`. Multi-rank work must scope identifiers by their rank/device context and establish explicit communication matching; timestamp proximity alone is not evidence of cross-rank dependency.
- `export_dag_guide.md` describes the current C++ pipeline and text format: `N M` header followed by nodes whose `children` are successors. Times are in microseconds; `bandwidth_gbps` actually denotes GB/s. Key schema extension points are `extractStreamId`, metadata filtering, the three node classifiers, and `collectSyncSignalFromLine`; field assumptions require synthetic coverage and later server-side confirmation.
- The Qwen3 profiling launcher `examples/mcore/qwen3/pretrain_qwen3_8b_4K_ptd_profile.sh` launches eight ranks but profiles only rank 0 over steps `[5, 6)`. For multi-rank capture, the server configuration must select all required ranks (`--profile-ranks -1` selects all); one rank's trace cannot establish the full multi-card graph.
- The available trace investigation notes are in `query.txt`; treat them as the current schema contract until real server traces can be inspected. A `trace_view.json` is a top-level event array, and its events do not carry rank/device/global-rank fields. Resolve event ownership from the containing trace's rank/device mapping; do not infer a card from synthetic `pid`/`tid`.
- Rank/world-size/parallel-group metadata is in the profiling directory, not the event array: use `profiler_metadata.json` (`distributed_args`, `group_info`/`parallel_group_info`), `step_trace_time.csv` (`device_id`), and device `info.json` as available. `ph=M` process labels such as `NPU:1` are useful labels but are not a substitute for the rank mapping. Rank-0 duplicate trace files under the same directory must be hash-deduplicated.
- For compute nodes, select `process_name=Ascend Hardware` and `ph=X`, retain only Task Types `AI_CORE`, `AI_VECTOR_CORE`, `MIX_AIC`, and `MIX_AIV`, and use numeric `ts` and `dur` in microseconds. Exclude CPU/Python/CANN/Communication/Overlap layers, `cat=cpu_op`, names beginning `hcom`, `Memcpy`, `Notify`, or `Reduce_Inline`, and task types such as `EVENT_RECORD`, `EVENT_WAIT`, `SDMA`, `SDMA_SQE`, `PCIE_DMA_SQE`, `Write Value`, `Notify_Wait`, and `PROFILING_DISABLE`. Do not use same-named CPU/CANN launch durations.
- For collective macro events, use `process_name=Communication`, `ph=X`, and names beginning `hcom` or `host`; `cat` may be empty. Exclude `hcom_send`/`hcom_receive` (P2P) and `Memcpy`, `Reduce_Inline`, `Notify_Record`, and `Notify_Wait` (microsteps). Derive collective type from the name prefix, `data_type` and `count` from `args`, and bytes as `count * dtype_size` only when no explicit size is available. Resolve rank participants through the rank-local group mapping and translate groups using `parallel_group_info`; a `group_name` string alone is not globally stable.
- Cross-rank collective records are one per participating rank and have no reliable global unique key: do not match them by `connection_id`, local sequence, `correlation`, name, or nearest timestamp alone. Match conservatively by translated logical group, collective type, count, and a bounded overlapping time window, then merge into one collective node with `participants=global_ranks`, `start=min(ts)`, `end=max(ts+dur)`, and preserved per-rank source records. `communication.json` is preferred for actual transit size/time/bandwidth; retain both communication time and bandwidth, and distinguish transit time from elapsed/wait time.
- Explicit dependency evidence includes `followed_by`, `hostOp`, `HostOpDevice`, `sync_task_queue`, `Notify_Record`/`Notify_Wait`, `EVENT_RECORD`/`EVENT_WAIT`, and task-queue/connection links. Pair flow events by `id` or `(bid,id)` where applicable. `correlation_id` is for enqueue/dequeue and `connection_id` is local launch-to-HCCL linkage; `Notify` IDs are not sufficient across groups without rank/context/time checks.
- Build same-card order separately per `Physic Stream Id`/`tid`; only add cross-stream edges when flow, notify, event, or task-queue evidence exists. Communication and compute can overlap, so never serialize all nodes by global `ts`; overlap-analysis records quantify overlap but do not create dependencies. For inferred edges, mark them `inferred`: link the last pre-collective compute/launch-chain node on each participant rank to the merged collective, and the collective completion to the first confirmed or nearby waiting compute node.
- P2P cannot simply be discarded: pipeline send/receive dependencies can be needed to preserve stage-to-stage reachability. If P2P is hidden from the public graph, retain a hidden/transfer edge or fold its dependency into the receiving compute node; do not drop the dependency. Keep communication microsteps out of public nodes unless they are needed as evidence for a launch/wait edge.

## Tests and verification

- `tests/ut/tools/test_chakra_trace.py` loads the offline tool by file path to avoid package import side effects, but normal pytest collection still loads `tests/ut/conftest.py`, which imports Megatron and MindSpeed-LLM. Its companion `sample_trace_view.json` is a fixture, not real profiling evidence; isolate the parent conftest before attempting offline pytest execution.
- General focused unit test: `python -m pytest -x --log-cli-level=INFO tests/ut/<area>/test_<name>.py`; narrow further with `::TestClass::test_method` or `-k expression`. Full UT is `python -m pytest -x --log-cli-level=INFO tests/ut` and requires the external ML dependencies even for mocked tests.
- Distributed tests are launched by the pytest hooks in `tests/ut/conftest.py`; do not prepend an extra `torchrun`. System tests require NPU, model/data paths, and baseline files, so do not run them on this workstation.
- Do not use `tests/test_run.sh` as a local test/help wrapper: it sources Ascend environments and clones/installs dependencies before parsing arguments.
- C++ changes should at least be checked with `g++ -O2 -Wall -Wextra export_dag.cpp -o /tmp/opencode/export_dag` and synthetic input; real trace validation remains server-dependent.
- The target multi-rank output should merge one collective node across participating ranks while retaining per-rank provenance, participants, collective type, communication time, bandwidth, and enough timing/stream/source fields for audit. Edges must be deduplicated and the result must be checked for cycles and missing/unknown participant mappings; unknown fields should be explicitly marked or rejected according to the selected strictness mode, never silently guessed.

## Formatting and repository-specific checks

- Ruff/Pylint/Bandit configuration lives in `pre-commit/pyproject.toml`, not a root `pyproject.toml`. Focused Python checks are `ruff check --config pre-commit/pyproject.toml <files>` and `ruff format --check --config pre-commit/pyproject.toml <files>`.
- Run `pre-commit run --files <files>` for the complete applicable hook set. Hooks include Ruff, Pylint, Bandit, codespell/typos, JSON/YAML checks, and clang-format; the local Gitleaks hook requires a separate `./gitleaks` binary.
- Hooks exclude `tests/mindspeed_llm/` entirely and exclude `mindspeed_llm/training/training.py` from Ruff formatting; preserve these exclusions for direct checks. C++ formatting uses root `.clang-format` (hook version 18.1.8).
- `setup.py` conditionally builds `ascendspeed_te_ops` only when TorchNPU and `ASCEND_TOOLKIT_HOME` are available; successful Python installation does not prove native operators were built.
